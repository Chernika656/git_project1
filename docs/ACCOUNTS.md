# Аккаунты, команды и права — этап 1

## Начать работу

Запуск прежний: `python3 web_app.py` или двойной щелчок по `Проектная среда.command`. Откройте http://127.0.0.1:8765.

1. Нажмите «Зарегистрироваться», укажите имя, почту, специализацию и пароль из 15–128 символов.
2. Подтвердите почту по ссылке из письма. Без подтверждения войти нельзя.
3. Войдите. Откроется личное пространство. Создайте проект или демонстрационный пример.
4. Через переключатель пространства создайте команду.
5. «Участники и команда» → «Пригласить»: укажите почту и роль. Приглашение действует 7 дней; его можно отозвать.
6. Приглашённый человек регистрируется и подтверждает ту же почту, входит и принимает приглашение.
7. Откройте проект → «Доступ» и назначьте участнику право просмотра, редактирования или управления.

Профиль открывается круглой кнопкой справа сверху: имя, специализация, цвет аватара с инициалами, запрос смены пароля и выход. Специализация выбирает стартовое представление: руководителю — слайды, бизнес-аналитику — BPMN, системному аналитику — UML, разработчику — API, тестировщику — требования, менеджеру — обзор. Другие виды доступны через переключатель.

## Почта в локальном режиме

Без SMTP письма **не отправляются в интернет**. Они сохраняются в `data/mailbox/*.eml`. Откройте последнее письмо как текст или в почтовой программе, затем перейдите по ссылке. В API нет списка писем или раскрытия токенов другим аккаунтам. Каталог имеет права 0700, новые письма — 0600. Локальные файлы предназначены для владельца компьютера и проверки приложения.

Для реальной отправки перед запуском задайте переменные окружения:

```sh
export WORKSPACE_SMTP_HOST='smtp.example.com'
export WORKSPACE_SMTP_PORT='465'
export WORKSPACE_SMTP_USER='workspace@example.com'
export WORKSPACE_MAIL_FROM='workspace@example.com'
# WORKSPACE_SMTP_PASSWORD задайте в окружении, не сохраняйте его в исходниках.
python3 web_app.py
```

Порт 465 использует SMTP SSL, остальные порты — обязательный STARTTLS с проверкой сертификата. Ссылка строится из `WORKSPACE_PUBLIC_URL`, по умолчанию локального адреса. Сервер по-прежнему слушает только 127.0.0.1. Для работы команды с разных устройств нужен отдельный этап размещения с HTTPS и обратным прокси. Для внешнего `WORKSPACE_PUBLIC_URL` приложение требует HTTPS и настроенный SMTP; cookie получает флаг Secure. Приложение не разворачивается публично этой правкой.

Подтверждение действует 24 часа, восстановление — 30 минут. Ссылка одноразовая. После восстановления пароля все сессии пользователя завершаются. Если доставка не удалась, можно запросить письмо снова через экран входа. Приглашение можно отозвать и отправить заново.

## Матрица доступа

| Роль команды | Полномочия |
|---|---|
| Владелец | Все проекты, участники, администраторы, передача владения |
| Администратор | Все проекты команды, приглашение и удаление обычных участников |
| Участник | Только назначенные проекты; может создать свой проект внутри команды |

У создателя проекта в команде возникает право управления этим проектом. Владелец и администраторы команды имеют полный доступ к командным проектам. Личное пространство доступно только его владельцу.

| Право проекта | Возможности |
|---|---|
| Нет доступа | Проект отсутствует в списке, запрос по ID отклоняется |
| Просмотр | Чтение, навигация, проверка BPMN, презентация, экспорт |
| Комментирование | На этом этапе эквивалентно просмотру; комментарии будут на этапе 2 |
| Редактирование | Изменения блоков, схем, требований, технического описания |
| Управление | Всё выше и назначение прав участникам этой команды |

Специализация в профиле не повышает права. Проверки выполняются сервером, а не только скрытием кнопок. При удалении из команды старые права на проекты удаляются, включая права автора проекта: возвращение по новому приглашению не восстанавливает их автоматически. Нельзя удалить владельца, повысить себя из участника или назначить администратора от имени другого администратора. Передача владения требует текущий пароль владельца и назначает ровно одного нового владельца; прежний становится администратором.

## Старые локальные проекты

До миграции они недоступны любым аккаунтам. Первая регистрация не присваивает проекты автоматически.

Перед первым обновлением схемы сохраняется резервная копия `data/workspace.pre-accounts.sqlite3`. Оригинальные документы проектов не переписываются при переносе. В `data/local-transfer.key` создаётся секретный ключ, доступный владельцу локальных файлов.

После регистрации выберите «Профиль» → «Перенести старые проекты» (также доступно на пустом стартовом экране), вставьте этот ключ и подтвердите действие. Все проекты прежней версии перейдут в **личное пространство** вошедшего аккаунта. Ключ используется один раз. Не публикуйте его вместе с базой или письмами. Импорт/экспорт JSON также остаётся доступен; импорт всегда создаёт новый проект в выбранном пространстве и не копирует чужие права.

## Устройство и проверки

- `facet/identity/accounts.py`: аккаунты, хеши паролей, сессии, токены, пространства, приглашения и ACL проектов.
- `facet/web/server.py`: API с авторизацией, CSRF и проверкой Origin/Host; открыты только статические файлы, health, auth/me и операции входа/подтверждения/восстановления.
- `frontend/js/account.js`, `frontend/css/account.css`: экраны регистрации и команд, режим просмотра и диалоги доступа.
- `facet/projects/workspace.py`: сохранение проектов; SQLite-соединения закрываются после каждого запроса.

Пароли хешируются scrypt (N=131072, r=8, p=1) с индивидуальной солью. Токены сессий, писем и приглашений хранятся в базе как SHA-256-хеши. Сессия живёт до 7 дней, простой ограничен 12 часами. Cookie HttpOnly и SameSite=Lax; защищённые изменения требуют CSRF-токен. Есть сохраняемые в БД ограничения частоты входа, восстановления, регистрации и приглашений. Требования к хешированию и сессиям сверены с [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) и [OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html).

```sh
python3 -m unittest discover -s tests -q
```

107 тестов: 90 проходят, 17 тестов старого оконного интерфейса пропущены без `BPMN_GUI_TESTS=1`. Проверены изоляция личных пространств, роли и попытки повышения привилегий, отзыв доступа, старые приглашения, перенос локальных данных, одноразовые ссылки, восстановление с отзывом сессий, CSRF, cookie и конфликт версий. Тестовые аккаунты и письма создаются в отдельной временной базе. В браузере проверены вход, создание команды/проекта, приглашение, выдача права просмотра и отключённое редактирование у наблюдателя.

Комментарии, согласования, история версий, корзина и совместное редактирование остаются этапом 2. MFA, внешний вход через Google и полноценный административный аудит не добавлялись. Это локальный MVP, без заявления о прохождении внешнего аудита безопасности.
