# Архитектура Facet

Приложение запускается одним Python-процессом и хранит данные в SQLite. Код сгруппирован по назначению; HTTP-сервер связывает модули и обслуживает интерфейс.

```text
facet/                  Python-пакет приложения
  __main__.py           запуск через python -m facet
  paths.py              корень проекта и пути ресурсов
  web/                  HTTP API, сессии, выдача файлов интерфейса
  projects/             модель проекта, SQLite, шаблоны, импорт презентаций
  bpmn/                 анализ, геометрия и редактирование BPMN
  identity/             аккаунты, команды, права, почта и согласования
  ai/                   вызовы модели, контекст анализа, планы изменений
  integrations/         Telegram Bot и Mini App
  desktop/              прежний интерфейс Tkinter
frontend/
  pages/                HTML-страницы
  js/                   JavaScript интерфейса
  css/                  стили
  assets/               логотип и изображения
  vendor/               сторонние библиотеки с лицензиями
resources/              CSS автономного BPMN-отчёта
examples/               учебные BPMN-файлы и генератор примеров
tests/                  проверки Python и JavaScript
scripts/                запуск сервера с открытием браузера
deploy/                 Dockerfile, Compose, Nginx и резервное копирование
docs/                   инструкции и принятые решения
data/                   локальные данные, исключены из Git
```

## Зависимости

- `web.server` использует проекты, BPMN, аккаунты, ИИ и Telegram. `web.assets` содержит явное соответствие публичных URL внутренним файлам.
- `projects.workspace` сохраняет проект и проверяет его структуру. Для HTML-прототипов вызывает существующую проверку `ai.agent.validate_prototype` через отложенный импорт.
- `bpmn` содержит разбор XML, проверки графа, диаграммы и команды редактора. Модуль не зависит от HTTP и аккаунтов.
- `identity.accounts` использует хранилище проектов; `integrations.telegram` использует аккаунты и интерфейс агента.
- `ai.agent` отвечает за запросы провайдеру и квоты, `ai.analysis` — за контекст и проверку отчёта, `ai.changes` — за проверку и применение плана. Существующая связь проектов с проверкой прототипов сохранена.
- `desktop` использует BPMN-модули. Веб-сервер не импортирует Tkinter.

Это перенос существующих модулей. Например, `identity.accounts` пока объединяет несколько операций аккаунта и команды, а `web.server` содержит маршруты API. Дальнейшее разделение этих крупных модулей можно делать отдельно с проверкой их контрактов.

## Пути, запуск и совместимость

Ресурсы, примеры и `.env` ищутся относительно корня репозитория через `facet.paths`, а не относительно перемещённого Python-файла. По умолчанию база остаётся в `data/workspace.sqlite3`; явный `--data` сохраняет прежнее поведение.

Основной запуск — `python3 -m facet`. Старые команды `python3 web_app.py`, `python3 checker.py` и `python3 app.py` поддерживаются небольшими файлами запуска в корне. Они передают управление пакету. Python-импорты внутри приложения и тестов используют полные имена `facet.*`.

Публичные HTTP-адреса, JSON-форматы, права доступа, квоты и формат базы не меняются. Перенос `frontend` не меняет адреса `/app.js`, `/style.css`, `/vendor/...` и остальных ресурсов. Сервер отдаёт только файлы из списка `STATIC_FILES`; исходники, `.env` и база в этот список не входят.

Docker собирается из корня репозитория командой из `docs/DEPLOY.md`. Конфигурация Compose использует `context: ..` относительно `deploy`, а `.env.production` по-прежнему находится в корне.

## Контракт ИИ при переносе

Входы остаются прежними: проект или выбранный блок, текст запроса, область анализа и пользователь. Выходы — проверенный отчёт анализа, HTML-прототип либо черновик плана изменений. Ошибки провайдера и квот передаются через `AgentError`, ошибки данных — через существующие проверки. Генерация использует серверный ключ и учитывает квоты; применение изменений остаётся отдельным действием пользователя.

Меняются только Python-пути импортов и расположение файлов. Проверки контрактов выполняются с подменёнными ответами модели, без реальных запросов к провайдеру и без ключа. Качество реальной модели и работа production этим не подтверждаются.

## Проверки и ограничения

После переноса прошла выборка из 81 Python-теста: HTTP и все 25 публичных ресурсов, авторизация, хранение проектов, BPMN CLI и отчёты, контракт агента, импорт PPTX и прототипы. Проверка сценариев JavaScript `node tests/test_scenario.js` также прошла.

Тест `node tests/test_presentation_import.js` падает на сохранении изображения при импорте слайда. Такой же сбой воспроизведён на исходном коммите `2cb4d064ff35513f0f4d5344ae7ad53b62ff614f`, до изменения структуры. Код интерфейса при переносе не изменяется.

Полный набор тестов, окно Tkinter и Docker-сборка не запускались. Docker отсутствует в текущем окружении; проверяется локальный запуск приложения и согласованность путей конфигурации.
