# BPMN Check

Первый прототип помощника системного и бизнес-аналитика: открываете BPMN-файл,
редактируете его в привычном редакторе, сохраняете — проверка обновляется автоматически.
Вся логика и оконный интерфейс написаны на Python. Нет API-ключей, аккаунтов и платных сервисов.

## Запуск

Нужен Python 3.10+ с Tkinter. В текущем окружении Tkinter доступен.

```bash
cd facet
python3 app.py
```

Нажмите **«Открыть схему»** или выберите учебный процесс в меню **«Примеры»**.
Сверху отображается схема, снизу — список замечаний и пояснение выбранного пункта.
Элементы с ошибками выделены красным, с рекомендациями — жёлтым.
Нажмите на замечание, чтобы выделить блок или стрелку сиреневым контуром.
Нажмите на элемент схемы, чтобы выбрать его первое замечание в списке.
Кнопки **«+» / «−»**, колесо мыши и **«Вместить»** управляют масштабом;
перетаскивание фона и полосы прокрутки перемещают схему.
После сохранения исходной схемы отчёт обновляется примерно за 1–2 секунды.
Кнопка **«Отчёт»** создаёт автономный HTML-файл для браузера.
Его оформление находится в `resources/report.css`: цвета, карточки, мобильная версия и печать.
При экспорте CSS встраивается в HTML, поэтому для отправки достаточно одного файла.
После изменения CSS создайте отчёт заново. Оформление самого окна находится в `facet/desktop/app.py`.
Приложение не отправляет схемы в сеть. После переноса элемента его положение
и связанные стрелки сохраняются в открытый BPMN-файл.

## Перемещение и полноэкранный режим

- **Двойной клик** по элементу или строке замечания подбирает масштаб под него:
  маленький объект приближается, большой помещается в область просмотра.
  В полноэкранной панели кликабельна вся ширина строки.
- **Перетаскивание блока** показывает новую раскладку со связанными стрелками.
  Отпустите кнопку мыши, чтобы сохранить изменение. `Esc` отменяет незавершённый перенос.
- При первой записи рядом создаётся резервная копия `имя.bpmn.bak`.
  Она не перезаписывается последующими переносами. Кнопка **«Отменить перенос»**,
  `⌘Z` или `Ctrl+Z` отменяет до 20 последних переносов в текущем открытом файле.
- Если BPMN изменился снаружи, перенос не записывается: загружается новая версия.
- **«На весь экран»** или `F11` открывает большой просмотр. `Esc` или **«Выйти · Esc»**
  возвращает обычное окно. Справа находится плавающая панель замечаний и подсказок:
  её можно перетащить за заголовок и свернуть кнопкой «−».
- Перенос дорожки, пула или развёрнутого подпроцесса перемещает содержащиеся в нём
  графические элементы. Действия остаются внутри своей дорожки: роли не меняются.
  Граничное событие переносится вместе с прикреплённым действием.
- При отсутствии BPMN DI сохранение добавляет координаты упрощённой раскладки.
  Изменяется первая отображаемая страница. Стрелки перестраиваются ортогонально,
  без автоматического обхода всех остальных блоков.

После обновления кода закройте старое окно и снова запустите ярлык **BPMN Check**
на рабочем столе — он открывает текущую версию проекта.

Если в вашей сборке Python нет Tkinter, используйте командную версию.

## Команды

```bash
# Проверка примера без ошибок
python3 checker.py examples/valid.bpmn

# Намеренно сломанный пример и отчёт для браузера
python3 checker.py examples/broken.bpmn --html report.html

# Автоматическая проверка после сохранения. Остановка: Ctrl+C
python3 checker.py examples/broken.bpmn --watch

# JSON для будущего плагина редактора
python3 checker.py examples/broken.bpmn --json

# Проверка исходного кода
python3 -m unittest discover -s tests -v
```

Код выхода: `0` — нет структурных ошибок (рекомендации возможны), `1` — найдены
ошибки или файл не прочитан, `2` — неверные аргументы или ошибка сохранения отчёта.
В режиме наблюдения JSON выводится по одному объекту на строку при изменениях файла.

## Что проверяется

**Ошибки:** повреждённый XML, отсутствующие или повторяющиеся ID, ссылки потоков
на отсутствующие элементы, пересечение границ подпроцессов, входящие потоки
у события начала, исходящие у события завершения, неверное прикрепление
граничного события, неверная ссылка на поток по умолчанию.

**Рекомендации:** неподписанные действия, ветки XOR/OR без формального условия,
недостижимые элементы, отсутствие пути к завершению в обычном графе.
Подписанные ветки без conditionExpression допустимы для описательных схем:
поэтому это рекомендация, а не ошибка.

Обычные вложенные подпроцессы проверяются отдельно. Граничные события учитываются
как возможные переходы от прикреплённой активности при анализе достижимости.
Отсутствие явных событий начала или завершения само по себе не считается ошибкой:
BPMN допускает неявные точки входа и выхода.

## Ограничения первой версии

- Это самостоятельное приложение и CLI, ещё не плагин внутри редактора.
- Оно проверяет, отображает BPMN XML и позволяет менять расположение элементов.
  Генерации по тексту, изменения условий/состава процесса и автоматического
  исправления смысловых ошибок пока нет.
- Просмотр отображает базовые события, действия, шлюзы, контейнеры и линии.
  Раскладка берётся из BPMN DI. При её отсутствии используется упрощённая сетка
  без визуализации вложенности. Показывается первая страница многостраничного файла;
  для замечания вне этой страницы выводится пояснение. Специальные маркеры событий
  и все детали нотации пока не воспроизводятся. Это базовый просмотр, а не полный BPMN-редактор.
- Это статический анализ графа, а не полная проверка стандарта или исполняющий движок.
  Нет XSD-валидации, моделирования токенов, проверки дедлоков параллельных ветвей,
  бизнес-смысла условий и messageFlow. Некорректные графические координаты
  пропускаются при отрисовке с уведомлением.
- Транзакции, событийные и ad-hoc подпроцессы проверяются частично с явным предупреждением.
  При компенсациях и прерываниях проверка завершения пропускается.
- Ссылки sourceRef/targetRef поддерживаются как локальные ID; квалифицированные ссылки
  с префиксом и ссылки на импортированные определения пока не разрешаются.
- Вход: BPMN 2.0 XML в UTF-8, до 5 МБ. DTD и ENTITY отклоняются.
- Наблюдение работает, пока приложение или команда запущены. После автоматического
  обновления HTML-отчёта открытую страницу браузера нужно обновить вручную.

## Как читать код

1. `facet/bpmn/checker.py`: `Issue` и `Report` — результат; `check_bytes` — разбор XML;
   `check_scope` — правила; `reachable` — обход графа.
2. `facet/desktop/app.py`: кнопки, список замечаний и наблюдение за выбранным файлом.
3. `facet/bpmn/diagram.py`: чтение координат из BPMN DI и упрощённая раскладка.
4. `facet/desktop/canvas.py`: отрисовка на Tkinter Canvas, подсветка, выбор, масштаб и перетаскивание.
   `facet/bpmn/editor.py`: пересчёт стрелок, сохранение XML, резервная копия и проверка конфликтов.
5. `tests/`: примеры для правил, чтения диаграмм и оконного интерфейса.
6. `examples/simple.bpmn`, `examples/valid.bpmn` и `examples/broken.bpmn`: схемы с координатами,
   которые можно открыть в BPMN-редакторе.

Базовые правила сверялись со [спецификацией OMG BPMN 2.0.2](https://www.omg.org/spec/BPMN/2.0.2/PDF).

## Проверено в этой версии

В наборе 58 автоматических тестов: 22 для анализатора, 7 для диаграмм,
9 для редактирования, 17 для оконного интерфейса и 3 для процесса закупки.
Они проверяют сохранение и отмену переносов, защиту от внешних изменений,
полноэкранную панель, приближение по двойному клику, цвета ошибок, выбор в обе стороны,
масштаб и обновление схемы после сохранения, в том числе очистку устаревшей подсветки.
Для командного режима проверено также восстановление файла во время наблюдения.
Оконные тесты включаются переменной `BPMN_GUI_TESTS=1`:

```bash
BPMN_GUI_TESTS=1 python3 -m unittest discover -s tests -v
```

В песочнице этой среды создание окна Tkinter аварийно
завершается; вне песочницы окно запускается и проверки проходят.
