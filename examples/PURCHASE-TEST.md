# Тест: согласование и оплата покупки

Откройте `purchase-mixed.bpmn` в BPMN Check. Для сравнения есть
`purchase-fixed.bpmn` — исправленный вариант того же процесса.

Оба файла содержат один пул «Компания», три дорожки («Инициатор», «Руководитель»,
«Бухгалтер»), 18 элементов процесса и 19 потоков последовательности.
Для чтения подробностей увеличьте масштаб кнопкой «+» или колесом мыши.

## Сценарий

Инициатор готовит заявку. Руководитель одобряет, отклоняет или возвращает её
на доработку. При одобрении параллельно собираются документы и рассчитывается
бюджет. После объединения ветвей проверяется наличие средств: либо счёт
оплачивается и документы сохраняются, либо инициатор получает уведомление
о нехватке средств. В исправленном варианте после оплаты сверяются реквизиты.

## Что должен найти анализатор

В `purchase-mixed.bpmn` ожидаются **3 ошибки и 4 рекомендации**.

| Тип | Где | Ожидаемое замечание | Исправление во втором файле |
|---|---|---|---|
| Ошибка | «Покупка оплачена» — `End_Paid` | Из конечного события выходит поток | Ошибочный возврат удалён |
| Ошибка | «Нужна покупка» — `Start_Request` | В начальное событие входит поток | Ошибочный возврат удалён |
| Ошибка | «Средств достаточно?» — `Gateway_Funds` | Default ссылается на чужую стрелку | Default указывает на ветку «Нет» |
| Рекомендация | «Одобрено» — `Flow_Approved` | Нет формального условия | Добавлено условие решения руководителя |
| Рекомендация | `Task_Archive` | Действие без подписи | Подписано «Сохранить платёжные документы» |
| Рекомендация | «Сверить реквизиты» — `Task_Audit` | Недостижимый элемент | Включён между сохранением документов и завершением |
| Рекомендация | «Уточнить обоснование» — `Task_Clarify` | Замкнутый цикл без пути к завершению | Возврат направлен на подготовку заявки |

В `purchase-fixed.bpmn` ожидаются **0 ошибок и 0 рекомендаций в рамках текущих проверок**.
Это не доказательство полной корректности BPMN или бизнес-процесса.

## Что сделано правильно в обоих файлах

- У каждого элемента уникальный ID, ссылки ведут на существующие элементы.
- Роли оформлены дорожками одного пула; потоки между дорожками допустимы.
- Параллельная подготовка имеет разделяющий и объединяющий шлюзы.
- Отказ руководителя и нехватка средств завершаются отдельными событиями.
- Графические координаты блоков и стрелок сохранены в BPMN DI.

## Дополнительная смысловая ошибка для ручного поиска

В смешанном варианте у шлюза наличия средств стоят условия
`available >= amount` и `available <= amount`. При равенстве подходят обе ветки.
**Текущий анализатор не вычисляет условия и не находит это пересечение.**
Оно не входит в счётчик 3 + 4. В исправленном варианте «Нет» — путь по умолчанию,
а формальное условие оставлено только для «Да».

## Проверка интерфейса

1. Откройте смешанный файл: три ошибочных элемента должны быть красными,
   четыре элемента с рекомендациями — жёлтыми.
2. Выберите строку «Средств достаточно?» — соответствующий шлюз выделится.
3. Найдите жёлтый блок «Сверить реквизиты» и нажмите на него — выберется его замечание.
4. Откройте исправленный файл: подсветка замечаний должна исчезнуть.

HTML-отчёты сохранены рядом с файлами. `generate_purchase.py` воспроизводит обе
схемы на Python, не меняя код анализатора.
