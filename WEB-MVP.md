# Проектная среда — веб-MVP

Локальное приложение для проектирования: проект → связанные блоки → несколько представлений. Сервер и работа с BPMN написаны на Python; интерфейс — HTML, CSS, JavaScript и SVG. Внешних зависимостей и доступа к интернету для работы не требуется. Нужен Python 3.10 или новее.

## Запуск

Двойной щелчок по `Проектная среда.command` в этой папке запускает сервер в фоне и открывает браузер. Повторный запуск открывает уже работающую веб-версию.

Или из терминала:

```sh
cd facet
python3 web_app.py
```

Откройте http://127.0.0.1:8765. Терминальный сервер останавливается через Ctrl+C. Другой порт: `python3 web_app.py --port 8766`. При изменении Python-кода перезапустите сервер; при изменении CSS/JS обновите страницу браузера.

Прежнее Tkinter-приложение запускается через `app.py` и остаётся доступным отдельно.

## Что работает

- Несколько проектов: создание, выбор, название и цель проекта.
- Блоки с названием, описанием, ответственным и статусом. Ответственный — текстовое поле, статус — отметка пользователя, без учётных записей и маршрута согласования.
- Доска: перетаскивание блоков, создание и удаление направленных связей, масштаб, перемещение фона и полноэкранный режим. Двойной клик по блоку открывает его BPMN.
- BPMN: импорт XML до 5 МБ, визуализация первой страницы, ошибки и рекомендации существующего чекера, двойной клик по замечанию приближает конкретный элемент. В полном экране — компактная панель замечаний.
- BPMN-редактор: шаблон начальной схемы, добавление задач/событий/XOR/AND, соединение элементов, перемещение с пересчётом линий и сохранением DI, изменение названия по двойному клику, удаление элемента со связями. Правка XML для других свойств, экспорт `.bpmn`, отмена последних 30 изменений в открытом проекте.
- UML sequence: участники, вызовы и ответы, изменение порядка и удаление сообщений, автоматическая отрисовка, экспорт SVG.
- Требования и API/данные: свободное текстовое описание с сохранением после паузы, экспорт TXT.
- Презентация: один слайд на блок, название/описание/ответственный/статус из актуального проекта; переключение стрелками, полный экран, экспорт всех слайдов в самостоятельный HTML.
- Экспорт проекта в JSON и импорт как отдельного проекта, включая BPMN, UML и все описания.
- Автосохранение в SQLite. При конфликте двух вкладок старая версия не перезаписывает новую: интерфейс предлагает экспортировать локальные правки и перезагрузить страницу.

## Данные и устройство

`data/workspace.sqlite3` — локальная база. Скачивайте резервную копию через меню ⋯ → «Экспорт проекта». Исходные `.bpmn` при импорте не меняются: редактируется копия внутри проекта, которую можно экспортировать обратно в файл.

- `web_app.py` — HTTP-сервер, JSON API и ограничения локального доступа.
- `workspace.py` — проверка модели проекта и транзакционное хранение.
- `bpmn_web.py` — команды BPMN-редактора поверх существующих модулей.
- `web/index.html`, `web/style.css`, `web/app.js` — веб-интерфейс.
- `checker.py`, `diagram.py`, `editor.py` — существующий анализатор, чтение и редактирование геометрии.

Сервер слушает только 127.0.0.1. Он предназначен для локального использования одним человеком. Регистрация, команды и роли доступа добавлены — см. ACCOUNTS.md. Обсуждения, автоматическое согласование и публичное размещение пока не реализованы.

BPMN и UML — независимые представления одного блока, автоматического преобразования между нотациями нет. UML пока только sequence, API — текстовый редактор. Презентация — последовательность слайдов по блокам, без свободной вёрстки и PPTX. Чекер анализирует BPMN-граф, не выполняет процесс и не заменяет XSD/проверку бизнес-смысла. Новые BPMN-элементы добавляются в первый процесс; создание пулов/дорожек и редактирование сложных свойств — через импорт/XML. Перемещение не меняет семантическую роль элемента. Автоматическая маршрутизация линий не обходит препятствия. Отмена в MVP относится только к BPMN и сбрасывается при перезагрузке; для резервных копий проекта используйте JSON-экспорт.

## Проверка

```sh
python3 -m unittest discover -s tests -q
```

80 тестов: 63 проходят без GUI, 17 тестов прежнего Tkinter-интерфейса пропускаются без `BPMN_GUI_TESTS=1`. Новые 22 теста проверяют SQLite, версии и конфликты, импорт, корректность модели, правки BPMN и HTTP API. HTTP-тестам нужен доступ к локальному сокету.

В браузере проверены создание проекта и блока, создание BPMN, изменение названия и геометрии с перезагрузкой, повторный зум по разным замечаниям и полноэкранный режим, создание участников и сообщений UML, техническое описание и слайд из содержания блока. Демо «Интернет-магазин» содержит четыре блока; в BPMN блока «Оплата» намеренно оставлены два нарушения и две рекомендации для проверки подсветки.

## UML для отдельной задачи BPMN

Двойной клик по задаче BPMN → описание задачи → «Создать UML» / «Открыть UML». У каждой задачи своя sequence-диаграмма. Кнопка «К BPMN» возвращает к исходной задаче; задачи с детализацией отмечены значком UML. Привязка хранится по ID и сохраняется при переименовании и перемещении. Общее UML-представление блока проекта остаётся отдельным. После удаления задачи её детализация хранится в проекте для восстановления через отмену; ручная замена ID в XML не переносит привязку автоматически.

В детализации задачи доступны **требования** и **критерии приёмки**. Их можно заполнить в окне BPMN-элемента или справа от его UML. Данные сохраняются вместе с проектом и включаются в JSON-экспорт; для участников с правом просмотра поля доступны только для чтения.

### Актуальность UML

В детализации задачи показывается «UML требует проверки». После проверки нажмите «Подтвердить актуальность» (нужно право редактирования и хотя бы один участник UML). Сохраняется снимок описания, требований и критериев приёмки: если любое из этих полей отличается, появляется предупреждение и значок `UML !` на BPMN. Само редактирование UML предупреждение не снимает — требуется подтверждение. Это ручная отметка соответствия требованиям, не автоматическая проверка правильности UML. Старые детализации без подтверждения считаются требующими проверки.


### Разделы приложения

Боковая навигация разделяет рабочую область, проекты (карточки и поиск), команду, аккаунт и настройки. В аккаунте можно изменить профиль и запросить смену пароля. Настройки сетки, панели свойств и анимаций сохраняются отдельно для каждого аккаунта в текущем браузере. Экспорт проекта доступен в настройках. Адрес раздела сохраняется в параметре `section`.


### Требования и ручной сценарий

В разделе «Требования» доступен реестр записей с названием, описанием, статусом и связями с задачами текущего BPMN-блока. Связи хранят ID элементов, переживают переименование и перемещение. Удалённая задача отображается как недоступная ссылка. Связанные требования раскрываются в карточке задачи. Доступ на редактирование проверяется существующими правами проекта; прежний текст требований сохранён отдельно.

Кнопка «Пройти сценарий» запускает ручной проход: выбор старта, переходы, выбор исключающей ветки, возврат назад. Тупики и отсутствующие цели показываются явно. Условия не вычисляются. Параллельные/включающие развилки, подпроцессы и специальные события пока останавливают проход с пояснением. Сценарий не меняет данные проекта.
