# Агент Facet и HTML-прототипы

Откройте блок → **✦ Агент**. Опишите интерфейс, нажмите **Сгенерировать HTML-прототип**,
откройте предпросмотр и примените результат. До применения проект не меняется.
Последнее применение можно отменить в этой же сессии. Прототип сохраняется в блоке,
попадает в экспорт проекта и в пользовательские шаблоны.

## Подключение

В корне `bpmn-checker` подготовлен локальный файл `.env`. Вставьте ключ:

```dotenv
OPENAI_API_KEY=ваш_ключ_OpenAI_API
OPENAI_MODEL=gpt-4.1-mini
FACET_AI_DAILY_LIMIT=500
```

Если файл отсутствует, скопируйте `.env.example` в `.env`.
Окружение сервера имеет приоритет над файлом. Настройки читаются при запросе,
после изменения ключа перезапуск не нужен. Ключ не возвращается в браузер,
не экспортируется в проект и исключён из Git. В интерфейсе: **Настройки → Агент OpenAI → Проверить подключение**.
Проверка запрашивает доступность выбранной модели, но не генерирует текст.

Общий лимит сервера по умолчанию — 500 успешных запросов в сутки UTC; администратор
может его уменьшить. Дополнительно для каждого пользователя действуют дневной лимит
тарифа и месячный лимит токенов. Ошибки подключения не расходуют запросы.
Счётчики хранятся в SQLite и не сбрасываются перезапуском. Это ограничение количества запросов,
не денежный бюджет. Выход ограничен 10 000
токенов, контекст блока — 80 000 символов. Автоматических платных повторов нет.
API оплачивается в аккаунте OpenAI отдельно от подписки на приложение.

Без ключа работает **Попробовать шаблон без ИИ**: локальная форма, проверка данных,
результат. Это демонстрационный шаблон, а не сгенерированный агентом ответ.

## Разница режимов

- **Пройти сценарий** — пошаговое исполнение модели BPMN, ветки, события и подпроцессы.
- **Запустить прототип** — кликабельные HTML-экраны: поля, таблицы, карточки, переходы,
  сохранение введённых значений между экранами, возврат и сброс. Окно можно двигать.

Агент получает описание, требования, BPMN, детализацию задач и текущий HTML-прототип
только выбранного блока. HTML-переходы — самостоятельная демонстрация интерфейса;
они пока не исполняют и не проверяют BPMN-движок. Внешние сервисы и бизнес-операции
имитируются. Шаблон без ИИ использует первую настроенную форму задачи, если она есть.

## Техническое устройство

`ai_agent.py` обращается к OpenAI Responses API через стандартную библиотеку Python.
Ответ имеет строгую JSON-схему: название, CSS и до 12 HTML-экранов. При сохранении
проверяются размеры, уникальные идентификаторы, существование целей переходов;
HTML очищается белым списком. Ошибки и отказы не применяются к проекту.

Доступ к генерации требует сессию, CSRF и право редактора проекта. Общий ключ
предназначен для закрытой установки с доверенными участниками; публичный сервис
использует тарифы и индивидуальные квоты.

Предпросмотр работает в iframe без `allow-same-origin`, с запретом сетевых запросов,
переходов верхнего окна и отправки форм наружу. Выполняется только статический
`prototype-bridge.js`; скрипты из ответа модели не допускаются. Формы переходят
по `data-go`, а `data-value` отображает сохранённое значение поля. Данные формы
существуют только до закрытия или сброса прототипа.

## Проверка

Автотесты интеграции не требуют ключа: ответы OpenAI подменяются тестовыми.
Без настоящего ключа невозможно подтвердить генерацию выбранной моделью и её
качество на реальных проектах. Перед показом подключённого агента выполните один
короткий пробный запрос на тестовом блоке.

Документация: [Responses API](https://developers.openai.com/api/reference/overview),
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

## Аналитика BPMN и проекта

В панели «Агент» доступны «Проверить BPMN блока», «Проанализировать проект» и
свободный вопрос по проекту. Контекст собирается сервером из сохранённого проекта:
цель, блоки и связи, словарь, требования, UML, API, детализация задач и HTML-экраны.
BPMN передаётся как семантические элементы без DI-координат вместе с результатами
обычного чекера. CSS прототипа не передаётся. В режиме BPMN другие блоки представлены
только индексом названий; полный контекст относится к выбранному блоку.

Отчёт содержит объяснение, приоритет, рекомендации, вопросы и следующие шаги.
Ссылки на блоки и элементы проверяются сервером. Пользователь может перейти к
элементу схемы и скачать JSON-отчёт. Последний отчёт хранится только в памяти вкладки,
при повторном открытии панели после изменения ревизии показывается предупреждение.
ИИ не меняет проект автоматически и не подменяет статическую проверку.

Доступ требует права редактора, сессию и CSRF. Анализ расходует ту же дневную квоту,
что и генерация. Контекст ограничен 180000 символами; превышение вызывает явную
ошибку с предложением проверить отдельный блок, без скрытого усечения данных.
